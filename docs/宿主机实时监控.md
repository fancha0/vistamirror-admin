# 仪表盘宿主机实时监控

服务器状态通过独立 Node Exporter 采集宿主机，VistaMirror 在后台计算实时速率和短期趋势。无需 Prometheus、Grafana 或新的数据库。

## 飞牛开发版部署

在 Mac 执行原有命令：

```bash
cd /Users/sy/my-todo
./scripts/deploy_fnos_dev.sh
```

脚本同步当前文件，在飞牛构建开发镜像，并启动两个开发服务：

- `vistamirror-admin-dev`：现有开发应用，默认端口 18091/18099。
- `vistamirror-node-exporter-dev`：宿主机采集器，默认监听 Docker 内网地址的 19100 端口。

远端辅助脚本会从 Docker 默认 bridge 网络读取宿主机地址，传给两个服务。不会绑定到 `0.0.0.0`，也不新增路由器或公网端口映射。采集器使用宿主机网络、PID、UTS 命名空间及宿主机根目录只读挂载，保证读取的是宿主机资源和主机名。

部署末尾会从应用容器检查采集器是否返回 CPU、内存、文件系统和网络指标。首次采样已有内存与存储数据，第二次采样（约 5 秒后）才显示 CPU 使用率、上传和下载速度。

本次代码与模拟验证没有执行远端部署；真实飞牛指标需部署后与飞牛系统监控对照核验。正式版 Compose 未添加采集服务。

## 指标口径

- CPU：连续两次 `node_cpu_seconds_total` 的差值，排除重复包含的 guest/guest_nice，按非 idle 时间占比展示；首次、计数器重置或长时间断线后显示采集中。
- 内存：`MemTotal - MemAvailable`，以可用内存而非空闲内存计算占用；容量单位为 GiB。
- 存储：按设备和文件系统类型去重，排除虚拟文件系统；默认优先 `/volN` 存储卷，可切换卷并展开列表。已用量为 size-free，可用量保留 avail，避免混淆预留空间。
- 网络：按选定单个接口的接收/发送字节计数差计算每秒速率；优先可用的 bond/team 接口，不累计其成员网卡。过滤 lo、Docker、veth 等接口。
- 每 5 秒采集 CPU、内存、网卡等轻量指标；文件系统单独每 30 秒采集。仅在内存保留约一分钟历史。
- 首页可见时每 5 秒读取后端快照，离开首页或隐藏页面后停止前端轮询。失败保留最后一次读数并显示过期时间；文件系统失败不阻塞 CPU、内存更新。

## 配置

可在 `.fnos-dev.env` 中设置以下非必填参数：

```dotenv
FNOS_NODE_EXPORTER_PORT=19100
FNOS_NODE_EXPORTER_IMAGE=prom/node-exporter:v1.12.1
# 默认自动发现；仅在宿主机禁用默认 bridge 等情况下手动指定 Docker 内网地址。
# FNOS_NODE_EXPORTER_BIND_IP=172.17.0.1
APP_HOST_METRICS_DISK=/vol3
APP_HOST_METRICS_INTERFACE=bond0
```

首页下拉框的选择保存在当前浏览器。自定义部署可设置 `APP_NODE_EXPORTER_URL` 为已有 Node Exporter 的 `/metrics` 地址；该地址仅在服务端使用，未配置时不启动后台采样。

## 排查

在飞牛开发源码目录执行：

```bash
docker logs --tail 80 vistamirror-node-exporter-dev
docker logs --tail 80 vistamirror-admin-dev
```

若 19100 已被使用，更换 `FNOS_NODE_EXPORTER_PORT` 后重新执行部署脚本。若文件系统读取失败，检查只读根挂载和飞牛存储卷挂载状态。采集器容器启动并不等于所有指标均正确，需以部署检查和首页实际读数为准。

宿主机部署参数参考：[Node Exporter 官方 Docker 部署说明](https://github.com/prometheus/node_exporter#docker)。
